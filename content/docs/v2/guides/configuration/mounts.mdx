## Introduction

A mount makes a directory on the node available inside a server's container. You might use one to share a large map, a mod pack, or a set of plugins between several servers, without copying the files into each server.

A mount has a **source**, the directory on the node, and a **target**, the path where it appears inside the container.

<Callout type="warn">
Servers only share a mount's files when they run on the same node. Mounts are not copied between nodes.
</Callout>

## Allowing the Directory in Wings

For security, Wings only mounts directories that its configuration allows. The Panel adds the source of every mount attached to a node to that node's configuration, under `allowed_mounts`:

```yaml
allowed_mounts:
  - /var/lib/pterodactyl/mounts
```

Wings reads its configuration when it starts, so it does not see mounts you create later until you update `/etc/pterodactyl/config.yml` and restart Wings. You may either:

- add the source directory to `allowed_mounts` in `/etc/pterodactyl/config.yml` yourself, or
- run the auto-deploy command from the node's **Configuration** tab again, with `--override`. This replaces the whole file, so only do this if you have not changed it by hand.

Then restart Wings:

```bash
systemctl restart wings
```

A directory in `allowed_mounts` also allows every directory inside it.

## Creating a Mount

Open **Admin → Mounts** and click **New Mount**. Fill in these fields:

- **Name:** A unique name for the mount.
- **Description:** Optional notes about the mount.
- **Source:** The absolute path of the directory on the node, such as `/var/lib/pterodactyl/mounts/maps`. Create the directory on each node you attach the mount to.
- **Target:** The absolute path inside the container, such as `/home/container/maps`. It cannot be `/home/container` itself.
- **Read Only:** Whether servers can only read the mount's files, not change them.
- **User Mountable:** Not used yet. Users cannot add mounts to their own servers, so only administrators can attach mounts.

Click **Create Mount**. On the mount's page, use **Attach Eggs** and **Attach Nodes** to choose where the mount may be used. A server can only use a mount that is attached to both its egg and its node.

## Attaching a Mount to a Server

1. Open the server in **Admin → Servers**, and select its **Mounts** tab. The tab appears once the server has been installed.
2. Click **Mount** next to the mount.
3. Restart the server.

The mount's files appear at the target path when the server starts. To remove the mount, click **Unmount** and restart the server.

<Callout type="info">
Mounted files do not appear in the Panel's file manager or over SFTP, even when the target is inside `/home/container`. Only the server's own processes can see them.
</Callout>
